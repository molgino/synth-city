# SYNTH CITY (R36S-Groovebox) – Projektkontext

Name **SYNTH CITY** (Repo `molgino/synth-city`, vorher R36s-Groovebox; interne Pfade/Binary/Dienst heißen weiter `groovebox`). Neo-Noir-/Synthwave-Optik (eigene Gestaltung, keine geschützten Film-Namen/Logos): Palette `C_*` + Neon-`TCOL`, Kopfzeilen-Linie Magenta→Cyan, Scanlines in `drawAll`, Splashscreen `drawSplash/runSplash` (Shot-Seite 40, `GB_SPLASH_T`, abschaltbar `GB_NOSPLASH`). Elektron-artige Groovebox (C++/SDL2, ALSA) für den Handheld **R36S** (RK3326, ArkOS 2.0, Kernel 4.4.189, glibc 2.30).
Sprache mit dem Nutzer: **Deutsch**. Anleitung für Nutzer: **`docs/handbuch.md`** (Quelle des PDF-Handbuchs; neue Funktionen dort beschreiben, Bilder per `![Unterschrift](shot:N)` mit N wie bei `--shot`). `tools/handbuch/build.py` (+ `style.css`) erzeugt `dist/SYNTH-CITY-Handbuch.pdf` (python-markdown, Pillow, Chrome headless; `--html` behält HTML), CI-Schritt im Build-Job, Asset in allen Releases, im ArkOS-Paket. `README.md` ist nur noch Kurzüberblick + Entwickler-Teil.

## Aufbau
- `src/engine.*` Sequencer + 13 Engines (KICK SNARE HAT CLAP SYNTH FM SMPL TOM RIM SHKR WTBL CHOP GRAN – Enum-Werte nur hinten anfügen, Anzeige-Reihenfolge `MACHINE_ORDER`), Wavetables `buildWavetables`, Insert-FX, Effekt-Busse (`fxbus.cpp`), Kompressor mit Sidechain; Mikrotiming `P_MTIM` (`pend`/`preDone`, negative Werte werden einen Step früher geplant)
- `src/params.h` alle Parameter. Speicherseiten je Spur (TRG SRC FLT AMP LFO1 INS SRC2 LFO2 LFO3 SEQ FLT2 ARP SRC3 SRC4 SRC5 SEND, je 8 = 128 Parameter; `LFO_BASE`, `LF_*`) und UI-Seiten `PG_*` (TRG SEQ ARP SRC SR2 FLT FL2 AMP LF1 LF2 LF3 INS | MIX FX CMP | PRJ SNG MST SET | LIVE | SR3 SR4 SR5 SND FXB FXC; Reiter in Ring-Reihenfolge); SET (=PG_SYS) ist eine Listen-Seite (`SetItem`, `drawSettings`), Mapping `PG_STORE`; FM = 4 OP/8 Algorithmen (`FM_MODS/FM_CARRIERS/FM_LAYOUT`); globale Skala `mst[MS_SCALE]`
- `src/main.cpp` UI (640x480): Kacheln (`tile`, Wert-Symbole `paramSymbol` nach Parametername), Engine-Symbole (`drawIcon`), Engine-Wähler, Grafiken je Engine (`graphKind`), Bedienung, Einstellungen, PC-Modus-Steuerung
- `src/web.cpp` + `src/webpage.cpp` Mini-Webserver (Port 80, sonst 8080): Upload-Seite für Samples/Projekte, Umwandlung im Browser; nach Upload `reloadSamples` (Bibliothek neu lesen, geänderte Pool-Dateien neu laden). API: `/api/list` (nur Anzahl + Projekte, kein Vollscan-Listing), `/api/dir?path=` (ein Ordner: dirs mit Anzahl, files), `/api/search?q=` (max. 400), `/api/info` (WAV-Kopf), `/api/mkdir`, `/api/rmdir` (rekursiv), `/api/move?to=` (Datei/Ordner, auch Projekte umbenennen), `/api/upload` (Unterordner werden angelegt, Projekte mit freiem Namen), `/api/delete`; `safeRel` erlaubt UTF-8, sperrt `..`, Punkt-Anfang, Steuer- und FAT-Sonderzeichen; Seite pollt nicht (nur bei Aktionen/Sichtbarkeit)
- `src/remote.cpp` Bildschirm-Spiegelung + Fernbedienung: Hauptschleife legt bei Zuschauer (`remoteWanted`) max. 30/s `remoteSnapshot(fbPix)` als RGB565 ab. **WebSocket `/ws`** (`remoteWsAccept` aus web.cpp `handle`, eigener pthread je Zuschauer, max. 3, 256-KB-Stack, SHA1/Base64 eingebaut): sendet Binärbilder (Format siehe Kopf remote.cpp, Differenz je Zuschauer `RemoteClient`, neues Bild erst wenn das vorige raus ist), empfängt Text `d A`/`u A` (Taste), `a LX -1` (Achse), `p <t>` → `P <t>` (Ping), `f` (volles Bild); Abbruch lässt alle Tasten los. Rückfall ohne WebSocket: `/api/screen?since=` + POST `/api/input?b=&v=`. Seite `/screen` (WEB_SCREEN in webpage.cpp): Bild per rAF, `fit()` hält 4:3, Querformat = Bedienung links/rechts, Touch mit Pointer-Capture + Wischen (`targetsAt`, Steuerkreuz 8 Richtungen), Tastatur (`km`), Gamepad-API (`gpMap`, Lage wie R36S), Zähler je Taste (`press/release`), **Verbindungsverlust** (`#lost`-Overlay über dem Bild, `setStat(false)` → `setLost`; Watchdog: Ping jede Sekunde, 5 s ohne Nachricht → `wsKill` + Neuaufbau, Aufbau-Timeout 4 s, online/offline/visibilitychange; Ton-Socket wird mit neu aufgebaut; Abfrage-Rückfall nur, wenn WebSocket nie ging), Wake-Lock, Vollbild, **Zoom** (`zm/zx/zy`, CSS-Transform auf `#cv` in `#cvw` overflow hidden, `applyZoom/zoomAt`, Knoepfe `zo/zl/zi`, Strg+Rad, + − 0; Pinch nur wenn zwei Finger < 150 ms nacheinander aufsetzen: erster Touch wird in `pend` zurueckgehalten, sonst normale Bedienung → P-Lock-Geste bleibt; `tPos` rechnet ueber getBoundingClientRect, gilt auch gezoomt); Screenshots-Test mit `GB_HEADLESS=1` + Playwright. **Touch aufs Bild**: Seite sendet `t/m/e id x y` (640x480), remote.cpp `touchPush` → `remoteTouchPop` im Hauptthread, `src/touch.inc` (`touchProcess` am Anfang von handleInput). Treffer über `hitAdd(x,y,w,h,HK_*,a,b)` beim Zeichnen (Registry `hits[]`, in drawAll geleert, `hitModal()` für Fenster darüber; Explorer/Tastatur/Editor/Export blockieren = per Steuerkreuz). Step = emuliertes A (`remoteDown/remoteHit`); im eingerasteten Lock-Modus: gleicher Step = fertig, anderer Step = `lockJumpTo`, Kopfzeilen-Knopf FERTIG (`HK_LOCKEND`); Explorer per Touch (`HK_FBROW` antippen = wählen, nochmal = öffnen/übernehmen, Samples beim ersten Tippen vorhören, ziehen = `fbScroll`; `HK_FBBACK/FBCANCEL/FBPLAY`-Knöpfe nur bei `remoteWanted()`); Web-Seite **Bild-Vollbild** (`body.full`, `setFull`, Taste V, schwebende Leiste `#fbar` SEL/START/⇆/✕), Kachel ziehen = `editValue`, neue bedienbare Elemente immer mit hitAdd anmelden. **Ton im Browser**: audioCb → `remoteAudioPush` (16 Bit Stereo in Ring `g_aud`, nur bei Zuhoerern), WebSocket `/wsa` → `wsAudioThread` (Pakete u32 Rate + u32 Position + PCM, >=512 Frames, faellt > 0,25 s zurueck → springt), Seite plant AudioBufferSources luecklos (Puffer 120 ms, playbackRate ±0,4 % nachregeln); AudioWorklet geht nicht (http = kein sicherer Kontext). **Web-App**: `/manifest.json` (start_url /screen, fullscreen, landscape), Icons `src/webicons.cpp` (PNG 180/192/512), `/sw.js` nur bei https/localhost
